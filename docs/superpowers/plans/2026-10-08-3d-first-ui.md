# 3D-first UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the always-mounted 3D world the base layer of the app, with the HUD, map tools and section panels as overlays on top of it.

**Architecture:** `App` renders one full-viewport `WorldStage` that never unmounts. The top bar, HUD, map tools, inspector and one `Panel` container (docked, wide or bottom sheet) sit above it. One "world focus" value (`selectedId`, `industry`, `linkMode`, `measure`) in `App` drives the scene. Panels update it when they open and through "Locate". A pure camera-maths module provides fly-to and the view offset that keeps the camera target visible beside an open panel.

**Tech Stack:** React 19, TypeScript (strict), Vite 8, Three.js 0.180.0 (bundled from npm), vitest 4 (node environment, pure-function tests only), oxlint plus Prettier, Playwright (fast-mode check).

**Spec:** `docs/superpowers/specs/2026-10-08-3d-first-ui-design.md`. Executors read the spec alongside this plan.

## Global Constraints

- Nothing under `src/sim/` changes. `git diff --stat -- src/sim` must be empty at every task boundary.
- `three` is pinned to exactly `0.180.0` and `@types/three` to `0.180.0` (dev). No other new dependencies.
- Kept selectors: the labels `Speed`, `Run simulation` and `Pause`, and the classes `.scenario-summary`, `.control-day` and `.run-indicator` (used by `scripts/validate-fast-mode.mjs`).
- Panel sizes: docked `min(560px, 42vw)`, wide `min(1100px, 92vw)`, bottom sheet `60dvh` below `860px` viewport width.
- Fly-to: `600` ms ease, comfort radius `30`, and a jump when `prefers-reduced-motion: reduce`. Existing zoom limits stay `14` and `95`, and the default radius stays `46`.
- Hashes: `#overview`, `#markets`, `#households`, `#government` and `#experiments` open panels. An empty or unknown hash means no panel.
- Copy: "Show on map" becomes **"Locate"**, and the panel close button is labelled **"Close panel"**.
- Validation: `npm run agent:check` (per `AGENTS.md`). Do not run typecheck, tests or build separately except to diagnose a failure. On failure, read only the failing stage's log in `.agent-logs/`.
- **Git:** `AGENTS.md` forbids commits unless the user instructs. Tasks end with a validation checkpoint, not a commit. If the user authorises commits during execution, commit at each checkpoint with the message given. Never add Claude attribution trailers. Work on a branch such as `feat/3d-first-ui`, not on `main`.

## Review Focus

These are the failure modes most likely to reach a user that the main tests don't cover. Each has its pinning test or check in the owning task.

1. **Stale selection after Apply settings or Restart.** After the household count drops, `selectedId` can point at a household that no longer exists. Today `HouseholdInspector` does `find(...)!` and would crash. The inspector must hide and selection must clear. Pinned by `selectedEntityKind` tests in Task 2, and used by `App` and `WorldStage` in Tasks 5 and 6.
2. **Locate while the world is loading or failed, or on the off-grid transport firm.** The selection still updates, the camera does nothing if there is no mesh, and nothing throws. Pinned by the `locate` return contract in Task 6 and the manual check in Task 7.
3. **Locate pressed again during a flight.** The new flight starts from the current, mid-tween pose with no snap back. Pinned by the `planFlight` mid-pose test in Task 3.
4. **Viewport crossing 860px while a panel is open.** The inset swaps between right and bottom, and the camera offset follows. Pinned by `insetFromPanel` tests in Task 3 and the manual resize check in Task 7.
5. **Deep link to `#experiments` on first load**, so the world initialises while paused. After closing the panel, the world must show the current day's state, not the day-0 scene. Pinned by the manual check in Task 6, step 7.

### Task 3: Camera maths

**Files:**
- Create: `src/ui/world/cameraMath.ts`
- Create: `src/ui/world/cameraMath.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const FLIGHT_MS = 600
  export const COMFORT_RADIUS = 30
  export interface CameraPose { x: number; z: number; radius: number } // target is on the ground, y = 0
  export interface ViewInset { right: number; bottom: number }
  export const NO_INSET: ViewInset // { right: 0, bottom: 0 }
  export function easeInOutCubic(t: number): number // clamps t to [0, 1]
  export function planFlight(current: CameraPose, entity: { x: number; z: number }, reducedMotion: boolean):
    { from: CameraPose; to: CameraPose; durationMs: number }
  export function poseAt(flight: { from: CameraPose; to: CameraPose; durationMs: number }, elapsedMs: number): CameraPose
  export function viewOffset(inset: ViewInset): { x: number; y: number } | null // null = clearViewOffset
  export function insetFromPanel(rect: { width: number; height: number } | null, narrow: boolean): ViewInset
  ```

- [ ] **Step 1: Write the failing tests:**
  - `easeInOutCubic`: `(0) === 0`, `(1) === 1`, `(0.5) === 0.5`, `(-1) === 0`, `(2) === 1`.
  - `planFlight({x:0,z:0,radius:46}, {x:5,z:-3}, false)` gives `to = {x:5,z:-3,radius:30}` and `durationMs = 600`.
  - `planFlight({x:0,z:0,radius:20}, {x:5,z:-3}, false).to.radius === 20` (never zooms out).
  - `planFlight(..., true).durationMs === 0`.
  - `poseAt(flight, 0)` deep-equals `from`. `poseAt(flight, 600)` and `poseAt(flight, 10_000)` deep-equal `to`. A zero-duration flight at `elapsedMs = 0` gives `to`.
  - Mid-flight replan (Review Focus 3): `const mid = poseAt(f1, 300)`, then `planFlight(mid, other, false).from` deep-equals `mid`.
  - `viewOffset(NO_INSET) === null`, `viewOffset({right:400,bottom:0})` gives `{x:200,y:0}`, and `viewOffset({right:0,bottom:480})` gives `{x:0,y:240}`. In a 1000px-wide canvas, a 400px panel leaves the visible centre at 300 = 500 − 200.
  - `insetFromPanel(null, false)` gives `NO_INSET`. `insetFromPanel({width:560,height:800}, false)` gives `{right:560,bottom:0}`. `insetFromPanel({width:375,height:480}, true)` gives `{right:0,bottom:480}` (Review Focus 4).
- [ ] **Step 2:** Run `npx vitest run src/ui/world/cameraMath.test.ts`. Expected: FAIL (module not found).
- [ ] **Step 3:** Implement `cameraMath.ts`. `viewOffset` returns half the inset on each axis, because `camera.setViewOffset(w, h, x, y, w, h)` shifts the image by −x/−y. `poseAt` linearly interpolates `x`, `z` and `radius` by `easeInOutCubic(elapsed / duration)`.

### Task 6: Panel-driven focus, fly-to, view inset and pausing

**Files:**
- Modify: `src/ui/world/scene.ts`, `src/ui/world/WorldStage.tsx`, `src/App.tsx`

**Interfaces:**
- Consumes: `focusForPanel` (Task 2); `planFlight`, `poseAt`, `viewOffset` and `ViewInset` (Task 3); and `WorldController` and `WorldStage` props (Task 5).
- Produces, in `scene.ts`:
  ```ts
  // Runtime gains:  flight: { from: CameraPose; to: CameraPose; durationMs: number; startedAt: number } | null
  //                 inset: ViewInset
  export function flyTo(runtime: Runtime, entityId: string, reducedMotion: boolean): boolean // false if no mesh
  export function setViewInset(runtime: Runtime, inset: ViewInset): void
  ```

- [ ] **Step 1: Focus on open.** In `App.openPanel`, when a panel opens (not when it toggles off), call `setFocus((f) => focusForPanel(next, f))`. The hash listener applies the same on hash-driven opens. Initial load applies it once for the panel from the initial hash.
- [ ] **Step 2: `setViewInset`.** It stores `runtime.inset`, then applies `viewOffset(inset)`: `camera.setViewOffset(w, h, x, y, w, h)`, or `camera.clearViewOffset()` when it is `null`, then `updateProjectionMatrix()` and marks the runtime dirty. The existing `resize` in `createRuntime` re-applies it after `camera.aspect` changes. `WorldStage` calls it from an effect on `inset` and once when the runtime becomes ready.
- [ ] **Step 3: `flyTo`.**
  - Gets the mesh from `runtime.entities`. If there is none, return `false` (Review Focus 2).
